# 实验室实验交付规则与清单

版本：1.0。生效日期：2026-10-29。适用于本仓库全部实验及后续船舶、反无人机验证。目标是让接收者无需重新调用大模型，就能看清实际做法、核对结果并决定下一步。

**每次运行都交代码、逐例结果、评分依据和操作报告。正向、阴性、失败或按门槛停止均可如实交付；只有汇总报告时，状态写“报告已收到，原始结果待复核”。**

## 一 必交清单

| 编号 | 交付物 | 最少内容与验收要求 |
|---|---|---|
| D01 | 目标与运行记录 | 实验号、唯一run_id、本次问题、起止时间、实际执行命令、输出目录、完成/失败/停止/未执行状态。计划和实际分开。 |
| D02 | 实际运行代码 | 真正执行的入口、全部自定义依赖及评分脚本；本仓库/外部仓库commit；执行时未提交改动的diff或源码快照。临时脚本也要交，不能只写一个文件名。 |
| D03 | 实际参数与提示词 | 最终生效配置、阈值、候选/查询/历史规则、预算；有大模型时交完整提示词和实际消息结构。说明开发选择过程、评价前冻结版本及偏离协议情况。 |
| D04 | 数据及模型来源 | 数据来源/版本、序列、模态、帧范围、初始化、开发/评价角色；真实模型型号、版本/revision、配置hash。离线自定义权重提供SHA256；可引用已校验manifest，避免重复下载或重复扫权重。 |
| D05 | 环境与执行日志 | Python、torch、transformers、CUDA、GPU和关键依赖版本；实际日志、错误、耗时。复用已有环境，不为记录信息重建环境或占GPU。 |
| D06 | 逐例机器结果 | 稳定case_id、序列、绝对源帧号、各臂预测/动作、有效/拒答/无效/NOT_RUN状态。连续跟踪交全部逐帧框；查询核验交全部预定查询，不能只交成功例。 |
| D07 | 真值与独立评分 | 实际评分脚本、标签版本/来源、逐例IoU/状态、UNKNOWN处理、各臂分母、汇总及配对改对/改坏。阈值和主对照只由开发数据确定。 |
| D08 | 结果解释及下一步 | 更新对应RUN_REPORT：执行了什么、哪些没有做、结果能支持什么、失败原因的证据和推断、继续或收缩决定。不得把调用成功写成效果有效。 |
| D09 | 文件位置与完整性 | 交付文件清单、路径/固定下载链接、大小及SHA256；明确哪些原始产物缺失、原因与影响。接收者能够按run_id找到所有证据。 |

旧实验未保存的信息写“未记录”，不能事后编造原始日志或把重建配置说成执行时配置。**补交材料默认只整理现有文件，不为补日志重新跑GPU。**

## 二 按实验类型追加

### 有大模型调用

- 实际发送的消息，逐张图片的参考/历史/候选角色、A—D字母、图像文件或可重建路径与hash；历史源帧严格早于当前。
- 原始回复及解析结果；拒答、无效JSON、异常、NOT_RUN分开记录。没调用不算成功拒答。
- 调用账本，包括属性提出/自检/诊断、失败尝试、重试及耗时；实际次数不得超过本次冻结预算。
- 标明实际输入是RGB、IR或双模态；不能因为数据集叫RGBT就称做了双模态实验。推理输入不得包含答案、当前GT、评分或后续标签。

### 有候选选择或跟断补偿

- 保存全部共享候选框、原生rank与raw score、打乱后字母映射，以及每臂选择的物理候选。原生rank1不能取打乱后的第一张图。
- Recall@K按全部候选最大IoU计算；不能拿某一选择器成功率替代。候选可达、选对身份、采纳后定位、后续恢复分别报告。
- 原局部、原生全局、干净首帧视觉、历史视觉、大模型分别列出实际结果。缺某对照写明原因，不能拿污染历史作为唯一强视觉依据。
- 同信息公平比较：冻结候选、裁图/预处理、历史上下文与预算。变更模型、输入或候选时单独记录，不混作同一增益。

### 有消失或可见性判断

- 可见有效、标注不可见/不存在、UNKNOWN分列；无效框不自动变成absence。
- 无消失标签就写“不适用/无法判断”，不能填“误接受0”。真消失不并入可见目标恢复率。
- “可见但local IoU<0.5”可以作事后子集；部署门控不能读取该GT条件。全量正常帧的改坏也必须计入。

### 有闭环反馈、训练或汇报媒体

- **闭环任务**追加：真实状态/模板/记忆写回日志、完整轨迹、恢复延迟及误恢复。离线任务写“未实现闭环”，不要求补做闭环视频。
- **训练任务**追加：数据划分、随机种子、训练配置/日志、可训练参数、checkpoint与实际epoch/耗时。未训练写“不适用”。
- **媒体可选**；任务已要求视频/图片时必交，并附case_id、序列、源帧、方法、原始结果路径。展示改好、改坏/无变化的代表例，不能只交剪辑成功片段。GT叠图只用于事后分析。
- **失败/停止任务**交最后完成阶段、异常原文、已消耗预算、已生成文件和缺失清单。保留原目录；达到预定停止门槛不需要为“验收正向”追加试验。

## 三 交到哪里

每个实验目录包含`README.md`、`RUN_REPORT.md`和本次交付清单。推荐小型交付目录：

```text
experiments/<实验目录>/received/<run_id>/
  DELIVERY_CHECKLIST.md
  RUN_REPORT.md
  actual_code/                # 实际入口、临时改动、评分脚本
  config/                    # 实际参数、提示与数据/模型来源
  results/                   # 完整逐例JSON/JSONL、评分与汇总
  environment/               # 版本、实际命令、运行/异常日志
  ARTIFACTS.md               # 大文件位置、大小、SHA256、缺失项
```

已有目录可保留原结构，用`ARTIFACTS.md`映射即可；不要移动正在写入的运行目录。

- 小型代码、JSON、Markdown进入Git。完整`runs/`仍为本地输出，不强推被忽略的整套目录。
- 大型消息日志、全量图片/视频放GitHub Release或明确可访问的结果归档；仓库保留固定链接及SHA256。单有服务器绝对路径不算完成回传。
- 模型、环境、缓存和整套原始数据不随结果提交。新数据依照来源和既定方案单独制包；实验室无外网时提供镜像或本地下载后经GitHub交付。
- 用现有`python scripts/export_results.py --run runs/本次目录 --include-media`可打包输出；**该工具按扩展名收集结果，未自动包含入口源码、diff或二进制数组，不能把这个ZIP直接视为完整交付。** 缺少的代码、依赖或其他结果须另附并在清单登记。
- 不删除或覆盖旧报告。修订另存版本，并注明哪些旧结论被何种证据修正。提交后给出仓库、分支、commit、交付目录和归档链接。

## 四 验收怎么判

| 状态 | 通过条件 | 可以怎样表述 |
|---|---|---|
| 报告已收到 | 只有汇总或关键原始文件缺失 | 已收到服务器报告；原始结果待复核 |
| 交付完整 | 必交项齐全；不适用项说明原因；历史确实缺失的产物如实登记并说明影响 | 本次材料已归档，缺失情况已说明 |
| 结果可复核 | 不重新生成模型结果即可复算主要计数；case映射、分母、主对照和调用账本可核对；关键缺失不妨碍该结论 | 指定结果已复算/输入输出已核对，注明尚存限制 |
| 有效性待判断/有线索 | 实现与结果可复核后，按冻结协议看配对净变化、正常误介入、消失误接受、序列差异与代价 | 只报告实际范围内的收益或阴性；不保证泛化 |

“交付完整”不等于方法有效；“没有正向收益”也不等于交付失败。关键原始记录缺失时，不把结果标为已复核。
